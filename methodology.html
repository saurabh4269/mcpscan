Methodology

Each score is 0–100, the sum of six factors. It's computed automatically from public data and is a heuristic signal, not a security audit.

FactorMaxHow
Maintenance25Days since last push: ≤30→25, ≤90→18, ≤180→10, ≤365→4, else 0. Archived repos get 0.
License10Recognised SPDX license 10; unrecognised/other 3; none 0.
Popularity15Stars: ≥1000→15, ≥300→12, ≥100→9, ≥25→6, ≥5→3.
Dependencies20Pinned versions from package.json, requirements.txt, pyproject.toml and go.mod checked against the OSV.dev API. 0 vulns→20, ≤2→12, ≤5→5, else 0.
Supply chain10npm provenance attestations 6, CI workflows 2, SECURITY.md 2.
Risky patterns20Regex scan of the top-level source files. Deductions: shell exec −8, eval/dynamic code −6, filesystem writes −3, outbound network −3. Many legitimate servers need these, so treat this as "capabilities to review" rather than "malicious".

Discovery

GitHub search (topic:mcp-server, topic:model-context-protocol, topic:mcp, "mcp server"), repos linked from the official modelcontextprotocol/servers README, and npm packages with keyword mcp-server. Forks are skipped; the top servers by stars are scanned. The crawl runs daily on GitHub Actions.

Spotted a wrong score? Open an issue on GitHub.
